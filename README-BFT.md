# HOU BFT 設備箱出借管理系統

HOU BFT Equipment Box Lending Management System

供伺服器系統廠／板廠使用，由 PED 產品工程部管理工程設備箱，產線人員依站別（Fixture）提出整箱借用。支援繁體中文／English、深色／淺色、桌機與手機。React 19 / Vinext / TypeScript。
目前主要使用方式為本機執行：Worker runtime 與 D1 相容的 SQLite 資料庫都在電腦上運作，資料保存於 `data/state/`，不需要雲端登入。

## 功能

- 儀錶板：設備箱總數、今日可支援、產線使用中、待我簽核、工程支援進度、實際零件內容與近 14 天申請／歸還趨勢。
- 設備箱：名稱、類別、平台機種、保管位置、狀態與工程備註；新增時自動編號，表單不需填設備箱編號、設備箱序號或管理單位／品牌，既有資料保留。箱內零件類別為 CPU、Memory、Motherboard、Storage、PCIe/Expansion、Network、Power、Cable、Heatsink、Other；逐項登錄名稱、獨立規格、料號及數量。零件序號不再輸入，既有序號資料保留。舊 DIMM／U.2 類別仍可查看與儲存。
- 產線申請：填寫站別（Fixture）、機種、用途及借用期間；不再填寫生產工單／工程單號；以整箱借用，伺服器檢查重疊時段；設備箱已借出時，不論新申請日期是否重疊都須等歸還後才能申請，前端同步反灰申請按鈕。
- 零件快照：提出申請時原子保存箱內清單；有待簽核、待借出或使用中的申請時，鎖定清單並禁止轉維護。後續變更不會改寫歷史快照。
- 點交：PED 管理人員逐項核對全部零件才能借出；借用人可歸還自己的設備箱，工程人員與管理員亦可辦理歸還；須記錄實還數量、正常／缺件／損壞及檢查備註。有缺件或損壞時，設備箱自動轉為待維護／補件。
- 簽核：核准、填寫原因駁回、申請人取消、簽核歷程；任何角色均不能簽核自己的申請。
  管理員與工程人員的申請會進入「PED 簽核中心 → 待他人簽核」。若沒有其他合資格簽核人員，可依提示新增或啟用 PED 工程人員。
  待簽核申請會保留設備時段，重複送出時可直接查看原申請；不會產生重複申請或操作紀錄。
- 成員：三層角色、部門、啟用停用、重設臨時密碼；首次登入強制改密碼。
- 帳號：修改顯示名稱、聯絡電子郵件、帳號及密碼；變更前驗證目前密碼，撤銷其他登入。
- 報表依產線及設備箱類別彙總；借用、設備箱與操作紀錄可匯出 CSV（Excel 相容 BOM 與公式注入防護）。支援通知中心、逾期提醒、操作與點交紀錄。
- 中英文與深淺色切換：登入頁、頂端工具列及帳號設定皆可使用；偏好保存在本機瀏覽器，重新整理後保留，無外部翻譯服務。使用者輸入的設備箱名稱、料號、工單與備註維持原文。
- 行動裝置：收合導覽、設備與借還卡片列、鍵盤可操作的原生對話框與減少動態效果支援。

## 權限

| 角色       | 資料範圍                               | 可執行操作                                 |
| ---------- | -------------------------------------- | ------------------------------------------ |
| 產線操作人員 | 自己的借用及相關操作紀錄；共用設備箱清單 | 提出與取消個人申請、歸還自己的借用設備箱、修改個人帳密 |
| PED 工程人員 | 全廠設備箱、借還及操作紀錄 | 跨部門核准／駁回其他人的申請；新增與編輯設備箱、設定維護或停用、領用歸還與檢查紀錄 |
| 系統管理員 | 全部資料 | 成員與系統設定、跨部門簽核、設備箱及借還管理 |

上述權限均由伺服器檢查。系統管理員亦不能自行核准自己的借用。
部門存於申請當下，調整人員部門不會改寫歷史申請歸屬。
PED 工程人員與系統管理員依角色取得跨部門簽核權，且不得簽核自己的申請；一般產線人員不能簽核。全廠借還資料可供設備點交使用；成員管理與系統設定仍僅限系統管理員。部門及角色由管理員指定。

## 第一次使用

開啟網站後，自行建立第一個管理員帳號與密碼。沒有公開或固定的預設帳密。
密碼長度為 6–128 字元，不限制必須混用英文字母與數字。可空白開始，或選擇載入 12 個伺服器設備箱、4 位停用產線成員及 11 筆示範借還。
新設備箱使用 `PED-0001`、`PED-0002` 這種流水編號；同時新增仍會分配不同編號。升級會縮短舊版自動產生的 UUID 長編號，保留設備箱 ID、手動編號與借用關聯。
範例不是公司的真實資產，頁尾標示「含範例資料」。啟用範例人員前須設定臨時密碼。

本機版使用獨立新資料庫，管理員由本機首次設定。原有雲端網站及資料仍保留，但不會與本機同步。
本機預設只監聽 `127.0.0.1`，不開放區域網路存取。
通知目前顯示於網站內，未連接外部 Email、簡訊或企業 SSO。
升級會保留原有帳號與歷史紀錄。舊設備需先補齊箱內零件清單才能提出新申請；原有無快照的借用可繼續完成，點交時需人工填寫內容。舊設備如仍有未結束申請，須先完成或取消後再更新清單。

## 本機啟動

需 Node.js 22.13 以上（建議 24）。最簡單的方式是雙擊專案資料夾內的 **啟動設備管理.cmd**。
也可以在專案目錄執行：

```powershell
npm start
```

啟動程式自動安裝缺少的套件、檢查來源異動並建置、套用尚未執行的 SQL migrations，再啟動 **http://127.0.0.1:3000**。
首次下載套件需要網路；字型已包含於套件，啟動完成後可離線使用。
一般重啟會沿用資料與建置；關閉系統不會刪除資料。
`--port 3001` 可改連接埠；`--data-dir outputs/local-qa` 可使用獨立測試資料；`--open` 會開啟預設瀏覽器。
目前的啟動視窗是系統主程序，按 Ctrl+C、執行 `npm run stop:local` 或雙擊專案內的 **停止設備管理.cmd** 停止；不會安裝 Windows 服務或開機啟動項目。

關閉系統後執行 `npm run backup:local`，或雙擊專案內的 **備份設備資料.cmd**，即可備份到 `data/backups/`。
備份會複製已停止的 SQLite state、資料庫識別檔與 schema migrations；請保存完整資料夾。
更完整的一般使用者說明見專案內的 **本機使用說明.md**。

## 驗證

```powershell
node node_modules/typescript/bin/tsc --noEmit
node scripts/run-framework.mjs build
node scripts/test-request-number.mjs
# API 測試請依下方說明，設定獨立資料庫及 BFT_TEST_URL。
```

API 整合測試僅接受 loopback 位置與尚未初始化的測試資料庫，會建立本機測試帳號與設備；不要對既有工作資料庫執行。
涵蓋初始化、三層權限、產線個人資料隔離、工程人員跨部門核准與駁回、自行簽核拒絕、工程人員設備管理與借還點交、零件快照、清單鎖定、缺件自動轉維護、中英文錯誤、重複預約、首次改密碼、CSRF、撤銷登入、停用與登入限流。
`scripts/qa-ped.mjs` 使用 taste-skill 的獨立測試瀏覽器；設定 `BFT_TASTE_ROOT` 與隔離測試站 `BFT_QA_URL`，並以隱藏 stdin 提供測試帳密；禁止正式 3000 連接埠。驗證繁中／English、深淺色偏好保存、不同角色與整箱點交流程。畫面與檢查報告位於 `.taste-skill/qa/ped/`。

## 資料與安全設計

密碼採每人獨立隨機 salt 的 PBKDF2-SHA256（100,000 次）；伺服器只存 session token 的 SHA256，Cookie 為 HttpOnly / SameSite=Lax，HTTPS 加 Secure，8 小時有效。
登入失敗 10 次將限流 15 分鐘。寫入檢查 Origin、JSON 類型與大小；SQL 使用參數化陳述式。
預約檢查與新增在同一 SQL 陳述式執行，狀態轉移含前置狀態條件；關鍵寫入與操作紀錄同批次提交。

`db/schema.ts` 是資料結構來源；SQL 與 metadata 在 `drizzle/`。
部署使用 `.openai/hosting.json` 的既有 project_id 與 D1 binding，Sites 在正式部署時套用 migrations。
操作紀錄畫面顯示權限範圍內最近 200 筆，資料庫仍保留更早紀錄。

系統角色為產線操作人員、PED 工程人員與 系統管理員。升級時，原「PED 設備箱管理員」帳號會轉為「PED 工程人員」，依新版角色權限取得跨部門簽核權；保留帳號、密碼、部門與歷史紀錄，該帳號需重新登入。

## 2026-10-27 介面與流程更新

- 「設備箱清單」說明改為「以整箱為單位借出。」；登入主標題為 HOU BFT 設備箱出借管理系統，英文為 HOU BFT Equipment Box Lending Management System，介面用語統一為 Box。
- 新增「我的借用設備箱」、本人歸還及已借出禁止新申請；原有清點、缺件維護、狀態與操作紀錄檢查保留。
- 簽核視窗同時提供綠色核准／紅色駁回選擇，支援跨部門簽核，駁回原因必填；仍禁止自行簽核。
- 申請編號改為清單第一欄，以申請建立時間的台北時區顯示 `BRyyMMddHHmm`。同一分鐘可顯示相同編號；內部 UUID 仍為唯一識別，不作資料鍵值遷移。
- 零件規格另存於現有 JSON 清單及快照；舊資料缺少規格時顯示空值，不覆寫原名稱。舊序號及 DIMM／U.2 類別保留相容性。
- 側邊欄「？」提供四步驟中英文操作說明；頁尾改為聯絡 TE／admin 的提示。

API 整合測試可在獨立終端啟動 `node scripts/local-start.mjs --port 3001 --data-dir outputs/api-qa`，再於另一個 PowerShell 設定 `$env:BFT_TEST_URL = "http://127.0.0.1:3001"` 並執行 `node scripts/test-api.mjs`。測試資料庫必須未初始化，測試輸出含測試帳密，請只供隔離測試使用。詳見主 README 的驗證步驟。
